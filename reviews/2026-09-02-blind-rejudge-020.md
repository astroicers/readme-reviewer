> 這是本工具**第一批真正的盲判資料**。此前 18 份判讀 + 重模擬全出自 rubric 作者,
> 每份報告都自我標註「不得充當 inter-rater 資料」。本輪補上那個洞。
>
> **所有統計由 `scripts/blind_agreement.py` 重算並斷言(掛 CI)**——
> 判讀值住在 `reviews/blind-2026-09-02/judges.yaml`,作者值 import 自

## 協定(污染防治是結構的,不是叮嚀的)

- **乾淨判讀包**:判讀者只拿到四樣東西——rubric 的 craft 段(`criteria.yaml`,
  逐字抽自 0.2.0)、形狀表(`shapes.md`)、`patterns.md`、12 份 README 原文。
  **包內經斷言確認不含任何語料 repo 名之外的判定線索**;判讀者禁讀 repo 其他檔案、禁上網。
  ⇒ 我的判定、兩批報告、重模擬值**結構上拿不到**,不靠自律。
- **三位判讀者、三種閱讀順序**(正序/倒序/亂序),彼此不知對方存在。
- 判讀者輸出**維度值 + 逐維證據 + rubric_friction 筆記**;
  **verdict 由呼叫端用 `craft_verdict_rollup()` 純函式算**,判讀者不碰。
- 材料限制與 18 份批次相同(只有 README 檔,無 repo)。

### 限制(先講)

1. **n=12,只出 percent agreement 描述統計、不算 κ**——姊妹專案已裁定該規模下分維度 κ 不可用。
2. **三位判讀者是同模型家族的 agent**(與 rubric 作者同源)——這不是人類 inter-rater,
   一致度可能被同源性抬高;分歧因此**更**值得信(同源都散,條文問題更實)。
3. 判讀值由我(作者)轉錄成 `judges.yaml`——逐字紀錄在同目錄可核對。
4. ⚠️ `judges.yaml` 與 verbatim 檔含具名 craft 判定,**未來的判讀者禁讀該目錄**。

## ⭐ 發現 1:R-004 兩面失穩,而**作者是離群值**

R-004 是唯一兩個一致度都塌的維度——而且方向很清楚:

- **作者 poor 5/12;三位判讀者合計 36 票中 poor 只有 2 票。**
- 判讀者互相 69.4%,對作者只剩 47.2%。

⇒ **我重模擬的 R-004 值系統性偏嚴,而且偏的是我,不是他們。**
最可信的解釋:重模擬時我從舊批(三出口版)的 poor **錨定移植**,只對三個機械同步實例
上調;盲判者拿新條文素讀,量詞與「陳述」門檻取寬讀,大批舊 poor 在他們手上落序 1/2。
條文的 `evidence_note` 寫著「本條若過度觸發,先懷疑它」——**盲判資料第一次給了這句話
獨立於作者的支撐**:失穩不在判讀者,在條文縫(見發現 3)。

有一格值得單獨記:`sindresorhus/awesome` 的 R-004 拿到 **poor(A)/ n/a(B)/ mixed(C)/
poor(作者)——取值域四個值出現三個**。三位都在 friction 裡指認同一個成因:
「外部連結本體算不算易腐內容」條文沒裁決,三個出口各有合法讀法。
**這不是判讀品質問題,是同一條縫的三種合法走法。**

## ⭐ 發現 2:R-005——新維度第二穩,而它的 anti-pattern 缺格位被**雙向**證實

上一批才加的 R-005 拿下 94.4% 兩兩一致(僅次於 R-001),
「缺席不設 poor」的設計沒有產生亂射;`choo` 的 freenode 死鏈三位一致 poor。

但 `public-apis` 那格是教科書級的條文缺陷證據:
**我判 mixed(套 anti-pattern:求助管道只在贊助商區塊),三位全判 good
(照 decision_order 走,anti-pattern 沒有落點)**——四方分歧的成因不是誰粗心,
是 **anti-pattern 清單與 decision_order 脫鉤**:同一件事,守序者到 good、
用 anti-pattern 者到 mixed,而兩者都是條文的字面。三位判讀者在互不知情下
**全部獨立點名了這個脫鉤**(A#4、B#5、C#5)。

## 這批能說什麼、不能說什麼

**能說**:
- 判準的骨架在盲判下站得住:整體兩兩 86.1%,R-001 完美,R-005(新維度)94.4%,
  形狀 11/12,verdict 分佈四方同為 7 needs-revision——**工具不是雜訊產生器**。
- R-004 的失穩有了獨立證據與**可指認的縫**(量詞、易腐定義、陳述門檻)——
  下一輪批次處理的靶心,而且這次不是作者自己說的。
- 0.2.0 的兩個改動拿到盲判佐證:索引/導覽型列讓 linux 的 R-002 從「查不了」變三方一致
  good;R-005 的保守設計(缺席≠poor)沒有亂射。

**不能說**:
- 「判得準」——一致 ≠ 正確;三位同模型家族,同源偏誤未排除。
- 任何比例的統計顯著性——n=12。
- R-004 該往哪邊修——盲判只證明縫在哪,修法要走誤判批次紀律。
